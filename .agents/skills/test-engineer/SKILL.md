# Test Engineer

Follow the project's existing test stack and test behavior through public interfaces where possible. Cover normal, boundary, failure, and regression cases without making tests depend on implementation details. Keep fixtures small, deterministic, and readable. Run the narrow test first, then the relevant suite; distinguish untested paths from passing evidence.
